## 結論與優先順序

這是**工程適配順序，不是畫質或速度排名**。候選模型沒有本機品質、毫秒數或記憶體排名。

| 需求 | 優先評估 | 理由與未完成條件 |
|---|---|---|
| 通用顆粒改善 | 連續、多尺度、具空間相關性的程序模型 | 可保留現有晚期顆粒階段，C#／WGSL 對應實作，是最小接入候選；仍須檢查格線、方向性、混疊與 CPU／GPU 一致性 |
| 可放大檢視的光學統計模型 | IPOL Poisson／Boolean 圓盤方法 | 粒徑／覆蓋率可解釋，pixel-wise 方法可按座標重建隨機狀態；計算量、取樣誤差、抗鋸齒與跨平台一致性均未量測 |
| 特定片種外觀重現 | 校準的片種掃描／統計重建 | 只有實測資料能支持片種宣稱，可搭配程序模型減少重複；資料散布權、尺度與掃描器噪聲拆分均未解決 |
| 中性點白平衡 | 使用者圈選中性 patch，自動模式只給候選與可信度 | 與目前渲染一致的正向試算路線；仍須處理混合光、剪裁、高光重建與邊界警告 |
| 膚色 | 獨立於全域 WB 的局部小幅修正 | 皮膚不是灰卡，不能反推唯一光源 |
| 曝光／階調 | 獨立測光工具，只調曝光／階調 | Zone 是工作曝光座標，不兼任白平衡 |

## 1. 顆粒：現況、選項與 UI

### 已確認的現況

- 現有實作是晚期輸出顆粒：[CpuPipeline.cs](../src/FilmBatch.Engine/Rendering/CpuPipeline.cs) `Grain` 與 [grain.wgsl](../src/FilmBatch.Gpu/Shaders/v1/surface/grain.wgsl) 做兩層 cell hash、以中間調為中心的亮度權重，再加到 RGB 並截斷到 0–1。不是感光元件噪聲模型，也不是完整底片乳劑模型。
- 現有 UI 已有強度、大小、粗糙度、彩色顆粒；[ModuleCatalog.cs](../src/FilmBatch.Core/Params/ModuleCatalog.cs) 的 `grain` 模組沒有顯示 seed 控制。照片種子已有確定性來源，見 [SeedHash.cs](../src/FilmBatch.Core/Random/SeedHash.cs) 與 `ModuleParams` 的照片種子合併。
- 已實際執行現有 CPU 顆粒：固定參數及 seed 重跑完全相同；以該參數組合輸出均勻亮度區塊時，實際畫面可見格狀結構。此觀察只針對該參數組合，不代表所有照片或候選方案。
- 純黑／純白附近有截斷造成的均值偏移，不能假設目前噪聲在所有亮度上都嚴格零均值。調查當時另有暫存工作目錄的觀察紀錄，未納入版本庫；本文件只保留上述可重述結論，不依賴那些暫存檔。

### 方案比較

| 方案 | 核心機制 | FilmBatch 接入與適用目標 | 主要限制 |
|---|---|---|---|
| 1. 連續／多尺度相關性程序顆粒 | 可重現的連續隨機場、空間濾波／多尺度混合、亮度相依振幅與通道相關性 | 保留現有晚期顆粒階段、C#／WGSL 對應實作；是最小接入候選 | 不是特定片種的量測；插值與濾波仍須檢查格線、方向性與混疊 |
| 2. IPOL Poisson／Boolean 模型 | 平面上的 Poisson 圓盤覆蓋；圓盤半徑可固定或服從 log-normal 分布；以 Gaussian aperture 與 Monte Carlo 估算觀測亮度 | 適合追求連續放大及可解釋的粒徑／覆蓋率；pixel-wise 方法可按座標重建隨機狀態 | 計算量、取樣誤差、抗鋸齒、CPU／GPU 一致性均須量測；不是完整顯影化學或三維光線追蹤 |
| 3. 校準的片種掃描／統計重建 | 多曝光均勻片段的掃描與統計，依亮度／色彩重建紋理 | 若要接近某個真實片種，提供實測依據；可搭配程序模型減少重複 | 必須自有或有散布權的資料；固定 overlay 會重複，尺度與掃描器噪聲須拆開；不能擷取商業產品內附資產 |

IPOL 原文的強度為 `lambda(y) = -ln(1-u(y)) / E[pi*r²]`，輸入 `u` 正規化到小於 1 的範圍。這不是把場景線性 RAW 直接當成底片光學密度；若要模擬負片／正片、各染料層或印相，還要定義相應響應與校準。每像素 N 次 Monte Carlo 取樣不等於只有 N 次固定成本的圓盤測試；pixel-wise 方法會搜尋局部 cell，遇到覆蓋即提前結束。

### 建議 UI 操作

以下為提案，不是已完成的 UI：

- **程序顆粒**：開啟顆粒 → 選「單色／彩色」 → 調整強度、粒徑、聚集／粗糙度 → 以 100% 與符合視窗交替檢查。進階項目再提供暗部／中間調／高光響應；重新隨機化只改 seed，不跟每次重繪變動。
- **光學統計模型**：由同一面板選模型，再顯示粒徑分布與觀測柔化／取樣品質。把粒徑和 Monte Carlo 品質分開；不要用提高「強度」來掩蓋取樣雜訊。
- **實測片種資料**：選片種及對應曝光響應，再調整放大倍率與顆粒量。未經量測的預設只能稱為外觀預設，不能宣稱某片種／ISO 的精確復刻。

共通約束：

1. 顆粒是創作輸出，不是 RAW 解碼時加入的感光噪聲。最小路線沿用晚期顆粒階段，不改 CFA／去馬賽克。
2. grain 座標與尺度應綁定一致的影像／片幅參考，不綁定 UI 視窗、crop 後短邊或 tile 起點；縮小代理圖需考慮像素覆蓋濾波，不能只改 cell 大小。
3. 固定照片、設定、seed 應重現同一底層紋理；CPU／GPU、分帶匯出及預覽／匯出要分別檢查。現有 `Gpu_MatchesCpu_OnFilmAndGrain` 的 64/65535 容差仍是既有契約，不與 RAW 收尾的 2/65535 混用，見 [EffectPipelineTests.cs](../tests/FilmBatch.Core.Tests/EffectPipelineTests.cs) 與 [RawGpuDisplayTests.cs](../tests/FilmBatch.Core.Tests/RawGpuDisplayTests.cs)。
4. UI 應區分感光元件 ISO 和模擬片種顆粒；兩者沒有可直接通用的換算。

## 2. 中性點 WB 與膚色輔助

### 最重要的接入限制

[RawSourceLoader.cs](../src/FilmBatch.Engine/Imaging/Raw/RawSourceLoader.cs) 在回傳 `Scene.Image` 前，已套用拍攝白平衡、相機／look 矩陣、可能的 ProfileTables／HueSat、高光重建、縮放、方向修正及可選相機局部階調；原始 `raw.Data` 已釋放。`ApplyColour` 還會處理負值及非有限值。因此不能把此影像當成未處理的感光資料，也不能宣稱一個反矩陣能無損恢復原始光源。

[CameraColor.cs](../src/FilmBatch.Raw/Color/CameraColor.cs) 的 `NeutralWhite` 可作為符合其前提時的候選初值；實際參數應透過現有 [RawWhiteBalance.cs](../src/FilmBatch.Engine/Imaging/Raw/RawWhiteBalance.cs) 的 `MatrixFor(T,tint)` 正向試算、衡量區域的中性殘差。這能追求與目前渲染一致的結果，不保證感測器域或光譜上的真值。若要求感測器域精確 WB，必須另有前處理取樣資料或受控重新開發，不是目前已具備的免費能力。

| 優先方案 | 操作與優點 | 限制／失敗條件 |
|---|---|---|
| 1. 使用者圈選中性 patch | 點選小區域或拖曳框選，排除離群樣本，顯示溫度／Tint 建議；使用者確認再套用 | 需實際中性物體；有色白牆、反光、剪裁、高光重建與混合光都可能造成偏差 |
| 2. 自動提出多個候選 | 結合亮度、空間一致性、中性可能性及 as-shot 先驗；可將現有 GreyWorld 作候選而非真值 | 明亮物體可能有顏色；單色場景與多光源無唯一解，不能強迫產生「高可信度」結果 |
| 3. 校準灰卡／色卡或參考照片 | 有已知參考時可做更可靠的重現，並在相同光源的照片間同步 | 需參考資料、色彩管理及光源一致；不是所有照片都能補做 |
| 4. 局部膚色輔助 | WB 完成後再選臉部／皮膚區域，檢查相對暖冷、綠洋紅偏移，作局部小幅修正 | 皮膚不是灰卡；不能從單一膚色估計唯一光源，更不應把所有人推成同一亮度／膚色 |

### 建議 UI 流程

以下為提案，不是已完成的 UI：

1. 在「RAW 原廠處理」增加中性取樣工具。單擊取小 patch，拖曳擴大取樣範圍；縮放、平移、旋轉、crop／鏡頭校正後仍須映射回同一來源區域。現有 [PreviewCanvas.cs](../src/FilmBatch.App/Controls/PreviewCanvas.cs) 的 `ActiveTool`／`ICanvasTool` 是可重用入口，但顯示 bitmap 本身不是正確取樣資料。
2. 顯示有效樣本、區域差異與剪裁／重建警告；沒有原始感光遮罩時，只能報處理後影像的可用性代理，不能稱為精確感測器飽和偵測。
3. 預覽前後差異，接受時一次切換 `raw.wb_mode=custom` 並套用 Kelvin／Tint，作為一筆可復原操作；取消不留參數變更。
4. 「自動」顯示候選位置及不確定性，由使用者接受或改選，不把最亮像素直接指定為白。
5. 膚色工具獨立於全域 WB。可以引用同一人物／同光源參考，或手動局部修正；不以固定 vectorscope 角度、`R>G>B`、人種或固定 Zone 當所有皮膚的標準。

參數邊界已確認為 2500–9900 K、Tint ±150；solver 達邊界或仍有明顯殘差應顯示警告，而非截斷後宣稱已中性。schema 的 50 K 是滑桿步距，不是必須量化到 50 K 的儲存格式，見 [ModuleCatalog.cs](../src/FilmBatch.Core/Params/ModuleCatalog.cs) 與 [ParamDef.cs](../src/FilmBatch.Core/Params/ParamDef.cs) 的 `Step` 定義。相對／擬合的 as-shot 刻度也不能自動當成實測絕對色溫。

參考：[Capture One 官方中性區域取樣說明](https://support.captureone.com/hc/en-us/articles/360002596138-Selecting-a-neutral-area-with-the-picker) 要求有細節的白／亮灰，排除 specular 與 clipped 區域。其頁面下方對拖曳平均的內容是使用者留言，不是官方宣告的既有功能；上面的框選操作是 FilmBatch 提案。

## 3. Zone III／V／VIII：測光與階調，不是白平衡

若 FilmBatch 明確選用線性 Y=0.18 作 Zone V 基準，可定義 `Zone = 5 + log2(Y/0.18)`。這是工作曝光座標，不能讀成物體、紙面反射率或螢幕亮度百分比。

| Zone | 相對 Zone V 曝光 | 選定基準下的場景線性 Y | 視覺／操作意義 |
|---|---|---|---|
| III | -2 EV | 0.045 | 暗部紋理的放置參考，不是先把它壓成純黑 |
| V | 0 EV | 0.18 | 工作中灰錨點，不代表所有測光表都以相同反射率校準 |
| VII | +2 EV | 0.72 | 用來說明「72%」是此處的相對場景值，不是通用白卡定義 |
| VIII | +3 EV | 1.44 | 很淡的高光紋理參考；大於 1 在場景線性域並不矛盾，不能直接對應顯示端 80% 或 144% 反射率 |

因此要修正原先文字中的幾個混淆：

- Zone VIII 不等於固定 70%／80% 反射率；物體反射率、照明、曝光、負片密度、紙面反射與顯示訊號是不同量。
- 白平衡只需要可信的中性色度；18% 灰卡可同時協助測光，但「是中性」不等於「一定是 18%」。[TE115 白平衡卡](https://www.image-engineering.de/products/charts/te115) 的官方規格就是 70% 反射率，不應因它不是 100% 就排除它。
- 光學密度是對數而不是百分比。例如透射率 T=70% 時，`D=-log10(T)` 約 0.155；這不是「70% 光學密度」。物體的 70% 反射率也不等於負片 70% 透射率。
- 傳統負片的「為暗部曝光、為高光顯影」與印相 dodge／burn 可借作操作思路，不代表數位 RAW 要模擬一次化學顯影就能自動還原它。

建議設獨立「測光／階調」工具：圈暗部 → 選「放在 III」調曝光 → 加高光取樣點、檢查 VIII 紋理 → 以高光壓縮／曲線調整跨度。若兩點不能同時到位，顯示跨度差異，不偷偷修改 WB。灰卡是曝光錨點時才選 V，膚色不強迫固定 V；完成 WB、曝光與階調後再判斷 film look 與 grain。這是工程提案，不是已實作功能。

參考：[出版社提供的 Zone System 書摘](https://s3-eu-west-1.amazonaws.com/s3-euw1-ap-pe-ws4-cws-documents.ri-prod/9780415730952/6th%20Edition%20Appendix%202.pdf)、[ILFORD split-grade printing](https://www.ilfordphoto.com/split-grade-printing/)、[Imatest ISO sensitivity／曝光與反射率](https://docs.imatest.com/docs/sensitivity-ei)。本次已驗算以上 EV、Y 與密度關係；沒有做相機測光表、紙材或顯示器的實體校準。

## 證據邊界：已觀察、推論與未知

- 已觀察：現有顆粒 CPU 實際輸出與確定性；現有 C#／WGSL 與 RAW 生命週期；官方論文模型、參考碼授權與產品公開描述；Zone 與密度算術。
- 工程推論：候選實作優先順序、面板／框選操作、座標與資料接入方式；不是已完成的 UI。
- 尚未知：候選模型真實照片盲評、Mac／Windows 延遲及峰值記憶體、CPU／GPU 數值一致性、跨尺寸／分帶紋理一致性、片種資料可散布性與精確感測器域 WB。
- 反對意見：程序模型不一定比校準掃描更像特定片種；物理統計模型不一定帶來最佳互動效能；一個使 patch 變灰的解不一定是原光源真值。這些限制保留，不以未量測的「最高品質」掩蓋。
- Sufficiency gate：主要機制與接入限制有已閱讀的程式／第一手來源；無法由本次資料決定的品質、速度、實體校準及授權問題均列為未知。足以完成 Survey，不足以宣稱任何候選已可上線。
