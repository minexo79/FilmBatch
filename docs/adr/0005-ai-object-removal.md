# ADR 0005：物件移除以選取、重建與接受結果分離

- 日期：2026-10-20。
- 狀態：**設計提議保留；續驗決定通用移除產品 NO-GO，沒有採用預設模型，T1 未通過、T2–T5 未開始**。
- 範圍：桌面／行動共用選取 UX、Engine 顯示域修補、逐張照片資產／復原、預覽及匯出。
- 證據：[來源 Survey](../object-removal-survey.md)；完整契約：[操作與資料設計](../object-removal-design.md)；相依切片與驗收：[實作計畫](../superpowers/plans/2026-10-20-ai-object-removal.md)。本文件不授權下載模型、外送照片、開始實作或 commit／push。

## 問題

「移除」不是一個演算法就能完整交付。物件選取可能遺漏影子／倒影；填補可能留下殘影、扭曲線條或產生新的物件；重新渲染時換一個生成結果則破壞使用者已接受的編輯。FilmBatch 還有 RAW 場景資料、CPU／GPU 效果、跨平台模型部署與逐張照片保存的邊界。

目前可重用的只有畫布工具、不可變照片命令、來源階段 ONNX 降噪與既有效果／匯出。DNG 語意遮罩不是手繪移除遮罩；既有降噪成功不能證明移除 graph 已支援 CoreML／DirectML／iOS。

## 本輪設計決策

### 1. 一個移除工具，兩個獨立問題

- **選取**：筆刷／圈選／加減選是基本路徑；EfficientSAM-Ti encoder＋decoder 可繼續研究為選取提案，SAM 2.1 未比較。真實照片續驗中單點可能只選局部，最高分正負點候選可能涵蓋鄰近物件；必須顯示、容許修正並由人確認，不自動套用。SAM 不是填補模型，也不保證物件、陰影與反射皆被選中。
- **重建**：同一已確認 mask 可以比較不同方法。初次產品實作只接一個通過資格的本機 AI 模型；確定性模型不偽造多個變體，傳統方法不冒稱 AI。沒有模型或不支援時明確失敗，不回傳原圖假成功。
- 使用者必須看過相同正式結果並接受，才寫照片狀態。生成、接受、停用、重生成、刪除各有明確語意。

### 2. 先比較候選，不宣告未量測的畫質冠軍

| 目的 | 優先調查／實驗 | 採用條件 |
|---|---|---|
| 本機工程對照，不是產品預設 | **MI-GAN-512 浮點核心** | 第一方 MIT 權重與原生數值通過，但大洞及真實移除有新物件／不相關形狀反例；保留研究控制，不開始通用移除整合 |
| 授權資格仍 blocked | **LaMa／big-lama 的具名轉換版本** | 等 exact checkpoint grant／owner 裁決才下載；不以 Apache 程式碼或鏡像標籤代替權重資格，也不宣稱工程／品質失敗 |
| 暫緩工程主線及產品採用 | **Moebius（2026）＋PixelHacker VAE** | 已測 `pretrained` 完整 .NET 鏈，但數值／貼回／資源未合格；VAE 與官方 SDXL VAE 實測不等價，不能直接更換。未測 `ft_places2` 只保留為有條件研究，不沿用舊圖資格 |
| 物件及影響一併移除的品質參考 | **ObjectClear、FLUX.1-Fill-dev** | 有限制的模型條款／產品使用資格與實際資源另審；目前不內建、不呼叫、不假設可免費商用 |

程式碼、權重、adapter／base、轉換器、資料與產品／API 是不同授權面。訓練資料來源限制需記錄並由適當 owner 審查，不能由模型評審直接宣布會或不會自動傳遞到權重。把權重移到另外下載或使用者匯入，不會消除適用的使用限制。

### 3. RAW 只正向現像，不反推

修補平面固定為 **`BasicDisplay`／`ToneSplit` 後、`Detail` 前的顯示 sRGB**。先修補，再做清晰／銳化、灰塵與顆粒，使新區域接受同一後段算子；不將 SDR patch 偽裝成未夾取 Rec.2020 RAW 或 HDR 高光恢復。

有修補的照片使用 canonical CPU 完整解析度參考管線，預覽／縮圖由同一正式結果縮小，匯出重播接受 patch。效果算圖模式與 AI provider 分開報告；沒有修補時保留既有 GPU／CPU 快速路徑。不改既有像素容差，不為移除另寫一套 GPU 神經網路。

這個選擇有實際代價：大圖上游編輯需重新建立完整基底，速度／記憶體待量測；選取畫面暫停後段效果。它避免在不同 backend 近似畫面或代理圖上接受結果，卻在輸出時換成另一個基底。

### 4. 保存結果，不靠 seed 重建

`PhotoEntry` 擴充不可變的逐張 `RetouchStack`，不混入可跨照片複製的藝術 `Settings`。接受的 bbox patch、確認 mask、向量筆劃、基底／幾何 keys 與模型來源存於專案自有資產，先資產、後 revision-checked JSON；沿用 `PhotoEditCommand` 做 undo／redo。格式升為 3，舊 1／2 讀成空修補，舊 app 不可無聲忽略後覆寫。

已接受像素在無模型／無網路時仍能重開／輸出。缺資產／損毀／錯基底則逐張失敗，不能略過修補或匯出時重新推論。普通 copy／paste 與 preset 不帶逐張修補；「重設此張」清除並可復原。資產 GC 必須保護保存狀態、undo／redo 及進行中的提交。

### 5. 上游變更要有恢復路徑

- 來源／幾何改變為**硬過期**：重新選取／生成或明確停用；輸出畫框座標不能假裝是 RAW 來源座標。
- 同來源／幾何的上游色調／降噪變更為**內容過期**：重新生成，或先預覽再明確接受「保留像素、重套用」；記錄 rebase 來源與目前 key，可復原。
- 修改前序操作使所有後序過期；不只依 mask 重疊，模型可能讀取全圖／ROI halo。
- 下游 detail／灰塵／顆粒變動不重推論。批次提供過期數量、逐張恢復與取消，不讓匯出無聲退回未移除照片。

嚴格遮罩外像素不變只在修補合成邊界成立。最終輸出的可影響區域須加上剩餘清晰／銳化／顆粒柔焦的完整濾波支撐，不能宣稱 grain 永遠是逐像素操作。

### 6. 本機推論為預設，雲端不是隱藏後備

沿用 [ADR 0002](0002-ai-denoise.md) 的固定 artifact 雜湊、顯式安裝、有界 native flight、取消後 token 檢查、真實 provider／fallback 報告。與降噪協調排程，不在 render 下載、不背景掃描整個資料夾推論。CPU 是合法的真實模型路徑，不要求所有節點都在 ANE／GPU。

雲端只列為未採用比較路線。若之後需要，另行決定供應商／付費／資料地區與保存政策，取得真正 ROI＋context 的外送同意並去除 EXIF／GPS；未知接單結果不得盲目重試。Lightroom／Photoshop 的產品功能不是 FilmBatch 可直接嵌入的 SDK 授權。

## 替代方案與反方

| 替代方案 | 好處 | 本輪不選為預設的理由／重新評估條件 |
|---|---|---|
| 只做 PatchMatch／Clone | 無權重、可提供手動來源控制 | 不能滿足大洞／語意重建目標；可作非 AI baseline，不是 AI 失敗後的偽裝替代 |
| 只用最大 diffusion／雲端 | 可能在大洞／複雜背景有較佳結果 | 授權、成本、隱私、原生閉包與記憶體未解決；合法比較顯示明顯優勢且取得使用者同意時重議 |
| 先 SAM 再固定填補、全自動套用 | 操作步驟少 | 選取信心不等於填補品質，影子／倒影與新物件仍需檢查；先作候選，不自動接受 |
| 在來源階段逆 tone-map 回 RAW | 裁切／色調改變可能更順手 | 一般 SDR 修補沒有可逆高光與感光資訊；無實際 RAW-domain 模型與證據不選 |
| 另存整張現像副本當來源 | 容易檢視和外部編輯 | 易讓既有上游參數失效或重複套用，且每次保存整張大圖；以明確修補 stage 保留參數契約 |
| 每次 render 依 seed 重生成 | 專案資產少 | seed 不保證跨權重／provider／版本同一像素，也可能再次付費；違反接受結果與離線重開 |

## 驗收與可推翻條件

1. **工程資格先於功能宣稱**：真實 artifact 的 CPU／目標 provider、數值、取消／重用、資源與完整原生閉包各自留證；iOS compile 或 Simulator 不代替實機。依 [ADR 0004](0004-apple-mobile-shared-core.md) 保留平台邊界。
2. **品質先於模型品牌**：依 Survey 固定場景／留出集／隨機盲評，記錄殘留物、新干擾物、結構／紋理／接縫、失敗率和總操作成本；未量測不得聲稱「最佳」。
3. **完整產品閉環**：設計的 OR-01–OR-14 由計畫 T1–T5 驗收。先有單一可用垂直路徑，不把 spike 或架構圖當交付。
4. **推翻點**：MI-GAN、LaMa、Moebius 同場比較，工程基準先跑不表示畫質先勝出；若三路均未通過品質／合法 artifact 資格，依 Survey 的候補與失敗原因重議。若 canonical CPU 的完整尺寸成本不可接受，才研究有數值與輸出一致性證據的 GPU stage，不先放寬畫質或重新生成。
5. **來源域重議**：只有可重現的場景域模型／色彩契約、完整幾何映射與真實 RAW／HDR 品質證據，才考慮把 stage 移到 RAW 來源；不能靠一個增益或漂亮 demo。

## 前置實驗與尚未驗證

前置 20 組執行與原始失敗保留於 [Survey 第 9 節](../object-removal-survey.md#9-本機可行性實驗)；[第 10 節續驗決策](../object-removal-survey.md#10-續驗與採用決策) 補上 34 組照片／選取 native strict pass、48 組高精度合成，以及 3 組真實 Moebius 完整模型鏈。**數值通過不代表移除品質通過**：MI-GAN 出現新的顯眼形狀，SAM 有負點／鄰近物越界反例；Moebius 固定噪聲後仍有數值漂移、近似貼回失敗與高資源成本。

因此目前不選任何模型為通用移除產品預設；MI-GAN 留快速對照、SAM 只留待人工修正的提案研究，Moebius 暫緩。LaMa 不下載。[第 11 節來源續查](../object-removal-survey.md#11-權重來源與後續研究) 的 VAE tensor 與 8 組 CPU 元件比較已否定直接視為 FP16 等價檔；原 `.bin` 的精確來源仍未閉合。先前只測 `pretrained`，不替未下載的 `ft_places2` 作畫質裁決；建議先做有條件的同場景開發比較，不先引入 PowerPaint／BrushNet 完整鏈。權利來源與條款差異見 Survey，不由此 ADR 作法律意見。

完整產品 alpha／UI／專案／undo／重開、40 場景／3 位人類盲評、full-frame 成本與 Windows／iOS 移除仍未驗收。T1 未通過，不開始 T2–T5，也不將小型瑕疵子功能偷換為原通用需求；若日後候選在既有 gate 通過再重議。修補 stage、接受像素保存、真實 provider 與平台 gate 保留，不新增 runtime 或放寬容差。
